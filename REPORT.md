# IncuBrix implementation and verification report

## Implemented in this workspace

- FastAPI jobs API with `/health`, `/ready`, `/api/v1/...`, OpenAPI documentation, idempotency keys, polling, structured JSON errors/logs, correlation IDs, and manifest/timeline artifacts.
- SQLAlchemy maps the existing SQLite job database. The queue supports atomic queued-job claims, WAL/busy-timeout settings, and a separate `python -m app.worker` process. Docker Compose now defines API and worker services sharing a persistent data volume, with MinIO artifact storage.
- Kokoro-82M is the default TTS provider and supports Kokoro English/Hindi voice identifiers. eSpeak and pyttsx3 remain alternatives. faster-whisper defaults to `small`/`int8`; non-English audio can be translated locally for stock-search hints while retaining the original transcript for captions.
- Stock search is bounded to two generated queries, five results per query, at most two configured credential-ready providers, five seconds per provider, and eight seconds total per scene. Abstract/non-visual scenes skip their own search. Each selected stock clip is assigned only to the scene that selected it; already-used provider asset IDs are excluded from later scene searches. Missing scenes receive their own text-free procedural illustration rather than inheriting a clip from another scene, and narration continues instead of failing or showing a blank frame. Illustrations are clearly labeled as generated artwork, not stock. Provider adapters retain license, download, media-integrity, and relevance checks; fallback does not select unverified or random footage. Normal stock selection uses the existing `0.20` threshold. If no candidate reaches it, the best candidate at or above the contextual floor (`0.17`) is marked with `fallback: true`, `fallback_reason: "no_high_confidence_match"`, and its `relevance_score` in the timeline. If every verified candidate scores below `0.17`, the highest-scoring verified candidate is selected as a last-resort fallback with `fallback_reason: "low_confidence_contextual_match"`; the manifest emits `LOW_CONFIDENCE_BROLL_FALLBACK`. These score-based fallback tiers retain license/media checks and configured close-call review, and require human relevance review. Last-resort use is disclosed, not calibrated evidence of relevance. Provider/query attempts, search duration, visual status, and fallback decisions are logged and included in warnings, `manifest.json`, and `timeline.json`. Internet Archive is automatically appended if omitted from a legacy provider-order setting and can be disabled with `INTERNET_ARCHIVE_ENABLED=false`. It confirms each item's declared CC BY, CC BY-SA, CC0, or Public Domain Mark license from item metadata and limits downloads to supported video files under 100 MiB. Keyed providers are skipped if credentials are absent. Pixabay search responses are cached for 24 hours.
- OpenCLIP also selects a scene-semantic crop anchor for each output ratio. Noto fonts are installed in the Docker image, and the artwork font selection supports Tamil/Devanagari script fonts when present.
- Optional Groq scene planning and an optional close-call vision reviewer are implemented. The vision reviewer submits one candidate frame plus its scene text, and rejects explicit relevance/logo/safety flags. It is deliberately labeled **un-calibrated**; no labeled calibration set or calibrated logo model exists.
- Optional signed terminal callbacks validate public HTTPS destinations and use HMAC-SHA256 with timestamp and correlation headers. API + worker mode uses SQLite as a single-host/single-worker queue; it is not a distributed broker.
- README, OpenAPI, AI-use disclosure, source/license inventory, and engineering report have been revised to describe the implemented behavior and limitations.

## Verification performed

- `python -m pytest -q`: **46 passed**. Coverage includes normal selection, 0.17-0.20 contextual fallback, below-0.17 last-resort selection, rejection when no usable candidates exist, bounded query generation, abstract-scene search skipping, provider timeout, previous-visual reuse, timeline/manifest disclosure, API, idempotency, SQLite compatibility/claiming, queue worker mode, catalog licensing, candidate ranking, Pixabay response caching, Kokoro adapter, Groq review contract, crop filter anchoring, signed callback HMAC, and recovery. Internet Archive fallback was verified using mocked API results and a mocked candidate verifier; the live catalog/download adapter was not exercised end-to-end.
- A real local Kokoro inference generated a **204,044-byte WAV, 4.25 seconds long**. It downloaded the Kokoro model and English phonemizer model on first use.
- A local API end-to-end run using explicit procedural-preview mode accepted a script (`202`), completed the Kokoro narration and procedural-visual render (`succeeded`, 100%), and downloaded the MP4 (95,128 bytes), SRT, timeline, and manifest. This validates the local pipeline and artifact routes, **not** real stock-footage relevance.
- Earlier in development, one Wikimedia Commons end-to-end render succeeded. A subsequent real user query returned `STOCK_FOOTAGE_UNAVAILABLE`, so that single success is not evidence of reliable catalog coverage. Pixabay/Openverse adapters were validated with mocked provider responses, not live account credentials. Internet Archive's metadata and licensed-video search adapter is covered by mocked tests; a suitable item cannot be guaranteed for every story.
- Pylance reported no errors; the workspace diagnostics include warning-level unused-symbol notices. `git diff --check` passed after the implementation and documentation edits.
- Docker/Compose validation and container builds **could not run**: the `docker` command is not installed in this environment. No hosted deployment was performed.
- No live Groq request, live Pixabay/Openverse request, or representative ASR performance test was made. The Groq scene text/vision paths are unit-tested with mocked responses.

## Not complete / evidence still required

- The local automated test suite is smaller than the 478 tests described in the proposed architecture. Do not claim the larger suite exists.
- No Modal app/deployment or Render/Vercel deployment has been created or tested. The Compose worker arrangement is for one host with one worker and a shared persistent volume; SQLite is not suitable for horizontal scaling.
- The 85% human scene-relevance target is **not established**. The evaluation ratings sheet remains blank, and Wikimedia has already shown a real no-result case. Internet Archive adds a no-key licensed catalog; configuring Pixabay and Openverse credentials can further broaden coverage. These catalogs still cannot guarantee matching footage for every narrative.
- There is no scientifically calibrated logo-detection probability model. Optional Groq frame verdicts are not calibrated and only run for close OpenCLIP scores; human inspection remains mandatory.
- The UI/API has no authentication or rate limiting. Keep it private or put an access-control layer in front before public hosting.
- Container build reproducibility, resource limits, cold-start time, hosted disk persistence, Hindi/Tamil speech quality, and multi-worker crash recovery still need deployment testing.
